# Design: auto-domain-skills

## Technical approach

### Capa pure-logic — `packages/core/src/skills/skillBuilder.ts`

Sin I/O, sin git, sin LLM. Recibe el grafo, devuelve archivos a escribir.

```typescript
export interface DomainSkillsOptions {
  nodes: ReadonlyArray<GraphNode>;
  edges: ReadonlyArray<GraphEdge>;
  minFilesPerDomain?: number; // default 2
  maxFilesShown?: number; // default 8
  maxTestsShown?: number; // default 5
}

export interface DomainSkillFile {
  path: string; // ".claude/skills/ctx-<slug>.md"
  domain: string; // "packages/core"
  content: string; // markdown ≤ 45 líneas
}

export interface DomainSkillsResult {
  files: DomainSkillFile[];
  skipped: Array<{ domain: string; reason: string }>;
}

export function buildDomainSkills(
  opts: DomainSkillsOptions
): DomainSkillsResult;
```

### Algoritmo

1. Filtrar `nodes.filter(n => n.type === "file" && n.path)`.
2. Agrupar por `getDomain(node.path)` → `Map<domain, FileNode[]>`.
3. Calcular `degree[nodeId] = inDegree + outDegree` recorriendo `edges` una sola vez.
4. Para cada dominio:
   - Si `files.length < minFilesPerDomain` → push a `skipped`, continue.
   - Ordenar por degree descendente.
   - Separar `code` (kind=code) y `test` (kind=test).
   - Cross-domain edges (solo edges `imports`):
     - `dependsOn[<otherDomain>]++` cuando `from` está en este dominio y `to` en otro.
     - `usedBy[<otherDomain>]++` cuando `to` está en este dominio y `from` en otro.
   - Generar contenido con plantilla determinista.
5. Slug: `domain.replace(/[/]/g, "-")`.
6. Path: `.claude/skills/ctx-<slug>.md`.

### Inferencia de purpose (sin LLM)

Pure string manipulation:

- Quitar extensión, quedarse con basename.
- Si nombre es "index" → usar el nombre del directorio padre.
- Convertir `camelCase` / `PascalCase` → kebab-case → "Title Case".
- Casos como `htmlTemplate.ts` → "html-template".
- Fallback: el basename sin extensión.

### Plantilla del skill

Heredoc determinista. Cada skill cabe en ~30-45 líneas:

```markdown
---
name: ctx-<slug>
description: Domain context for <domain> — <N> files, <M> tests<dependencyClause>
tags: [<domain>, domain-skill]
---

# <domain>

<N> code files · <M> tests · <X> cross-domain links

## Key files

- `<path>` — <inferred-purpose>
  ... (top archivos por degree, max maxFilesShown)

## Depends on

... (omitir sección si vacío)

## Used by

... (omitir sección si vacío)

## Tests in this domain

... (omitir sección si vacío)

## Quick commands

- `forge context "<task in <domain>>"` — pack focused on this domain
- `forge spec <change-id>` — OpenSpec scaffold (will infer domain automatically)

_Auto-generated by `forge skills`. Run `forge skills --force` to regenerate._
```

### Capa CLI — `cmdSkills` en `packages/cli/src/index.ts`

Patrón idéntico a `cmdDocs` ya existente:

- Lee `.contextforge/graph.json` (usa `readRequiredJson` con hint).
- Llama `buildDomainSkills({ nodes, edges })`.
- Por cada `DomainSkillFile`: si existe y NO hay `--force` → skip; si no existe o hay `--force` → escribir.
- Reporta dominios omitidos al final.

### Data flow

1. `forge scan` → `.contextforge/scan.json`
2. `forge graph` → `.contextforge/graph.json`
3. **`forge skills`** (NUEVO) → `.claude/skills/ctx-<domain>.md` (uno por dominio)
4. Claude Code auto-carga el skill por `description` + `tags` cuando el dev abre archivos del dominio

### Coexistencia con skills existentes

| Tipo            | Naming                   | Origen                       |
| --------------- | ------------------------ | ---------------------------- |
| Task-oriented   | `contextforge-<task>.md` | Curados manualmente          |
| Domain-oriented | `ctx-<domain-slug>.md`   | Generados por `forge skills` |

Diferentes prefijos, diferentes propósitos, no interfieren. `forge impact` (S11) seguirá detectando coverage de ambos.

## Risks

| Riesgo                                                            | Mitigación                                                         |
| ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| `purpose` inferido sin LLM puede ser pobre para nombres ofuscados | Fallback al basename limpio; aceptable porque es solo decoración   |
| Skills generados podrían contradecir skills curados               | Naming `ctx-*` los separa del prefijo `contextforge-*`             |
| Sobrescribir trabajo manual del dev                               | Default no sobrescribe; requiere `--force` explícito               |
| Grafo desactualizado → skills obsoletos                           | El dev corre `forge sync` (S11) o `forge graph` antes de regenerar |
| Dominios pequeños (1 archivo) generan ruido                       | `minFilesPerDomain: 2` por defecto; reportar en `skipped`          |

## Tests

- `packages/core/__tests__/skillBuilder.unit.test.ts` con ≥ 8 unit tests.
- Coverage del nuevo módulo ≥ 90%.
- Coverage global ≥ 80% (mantener threshold).

Casos cubiertos:

- Empty input → empty result
- Dominio con 1 archivo → `skipped`
- 2+ dominios con suficientes archivos → skills generados
- Cross-domain edges → secciones "Depends on" / "Used by" correctas
- `maxFilesShown` limita
- Slug correcto para `packages/core` y `src`
- Frontmatter conforme (`name`, `description`, `tags`)
- Description menciona N files / M tests / deps cuando aplica
