## CLI commands (`pnpm forge <cmd>`)

```
init       — scan + graph + skills + context + viz in one shot
scan       — index files, emit scan.json (no LLM, deterministic)
graph      — build dependency graph from scan.json (no LLM, deterministic)
             --force           rebuild ignoring cache
             --with-calls      include regex-based call edges (noisier)
             --with-semantic   emit Pass-5 semantic layer
context    — select context via PageRank + BFS + greedy budget
spec       — scaffold OpenSpec change from context-pack
implement  — generate implement-plan.json with guardrails
viz        — generate graph.html for browser visualization
docs       — scaffold Diátaxis docs structure
skills     — auto-generate domain skills from graph
manifest   — build agent-manifest.json (per-task skill selection)
sync       — detect drift between implement-plan and working tree
impact     — health check + blast-radius report
```

## MCP tools (`packages/mcp`)

Call priority order for a new change:

1. `forge_status` — check artifact freshness and list active changes
2. `forge_change_subgraph` — load frozen scope if working on an existing change
3. `forge_change_context` — read context.md for navigation map
4. `forge_context` — select files for a new task (PageRank + budget)
5. `forge_neighbors` — walk one edge further from a specific file
6. `forge_domain_map` — high-level domain overview
7. `forge_semantic_map` — layers, endpoints, flows
8. `forge_flow` — detail of one flow from semantic map
9. `forge_spec` — scaffold OpenSpec change from context-pack
10. `forge_implement` — generate implement-plan.json
11. `forge_check` — validate implement-plan guardrails
12. `forge_rebuild_graph` — re-scan + rebuild graph (no shell needed)
13. `forge_archive_change` — close a change and refresh parent graph
14. `forge_change_manifest` — scoped agent-manifest for a change

## SDD recipe (standard agent flow)

```
forge_status
  → if active change exists: forge_change_subgraph → forge_change_context
  → if new task: forge_context { task, seeds, budget }
      → forge_spec { change_id }
          → implement files listed in context-pack
              → forge_check
                  → forge_archive_change { change_id }
```

## Repo conventions

- `forge scan` and `forge graph` must never call any LLM.
- Per-file cache at `.contextforge/graph.cache.json` — do not commit.
- Generated artifacts in `.contextforge/` are gitignored except `templates/` and `structure/`.
- All JSON outputs must pass `validateOrThrow` before being written.
- Exit code 1 = IO/runtime error; exit code 2 = schema validation failure; exit code 3 = fatal.
